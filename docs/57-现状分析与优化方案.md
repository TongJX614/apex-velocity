# 57 · 现状分析与优化方案（按优先级排列）

> 基线：v0.54（2026-11-06）。本文为**评估与方案**，不包含实施改动；按约定「经确认后逐步实施」。
> 评估方法：通读核心脚本（car / ai_car / race_manager / main / settings / ui_style / theme_scenery 等）、
> 资产盘点、`--verify` / `--audio-test` 无头跑测实测。

---

## 一、总体结论

项目成熟度**远高于典型独立赛车游戏**：45 台车真车数据标定、8 条赛道、改装系统、
程序化 + CC0 真实资产混合管线、四档画质、成就/成长/双人分屏均已落地。
当前最紧迫的不是「继续堆内容」，而是：

1. **P0 回归**：`--verify` 穿模审计从 v0.54 的「8 图清零 PASS」**退化为 8 图全 FAIL**（详见二.1）；
2. **工程风险**：项目 4.8GB、2.7 万行 GDScript，**无任何版本控制**，一次误操作即可摧毁多轮迭代成果；
3. **性能上限**：车模 0 LOD、45 台合计 992 万三角面、比赛画面 ULTRA 档 38–62fps，模型精度与帧率的矛盾只能靠 LOD/减面管线解决，而不是继续换更高模。

「3A 级画面」在当前 Godot Forward+ 技术栈与自持资产条件下不可达，**可达的现实上限**
是「商业街机赛车品相」：真实感环境 + 稳定 60fps + 完整玩法闭环 —— 这也是本方案的目标。

---

## 二、现状盘点与关键发现

### 1. 【P0】穿模审计全图 FAIL（新回归）

实测（2026-11-06，本机 headless `--verify`）：

```
[M1] FAIL: track coast:  268 scenery objects on the road
[M1] FAIL: track city:  1718   harbor: 2030   skyline: 1762
[M1] FAIL: alpine: 347   canyon: 629   glacier: 338   magma: 560
[VERIFY] FAIL (8)
```

其余验收段（M2 车库 / M3 夜赛·天气·碰撞 / M4 场地植被 15.91m 净空）全部正常，
比赛模拟本身 P1 完赛、成绩与纪录落盘正常 —— **纯装饰摆放层面的问题**。

主要违规来源（审计 top offenders）：

| 类别 | 典型节点 | 数量级 | 性质判断 |
| --- | --- | --- | --- |
| 城市装饰子件 | `CityBlocks/CityCornerFins / RooftopUnits / Ledges / EntranceNeon` | 单图 300–1700 | 楼体贴路夹道（v0.52 主题化设计）的**装饰子网格超出主楼净空** |
| 港口集装箱 | `HarborContainers` | 1670 | 集装箱堆场贴路摆放 |
| 地表碎石/砾石 | `DesertGravel / CoastPebbles / ValleyGravel` | 数百 | `_scatter_gravel` 最小离路 1.6m + 2.6m 净空，但**审计阈值是 half+0.5m**，两者天然冲突 |
| 路肩设施 | `DesertReflectors`（反光标记）、CableCarLegs | 100+ | v0.52「贴边不压路」的**设计意图**与审计判定不一致 |

诊断结论（两种成因并存，需分别处理）：
- **设计/审计冲突**：砾石、反光标记、轮胎墙等路肩装饰的摆放参数（≥1.6m 离路）早于
  v0.54 的「压路 = 违规」审计口径，审计豁免名单（grass/lawn/mark）未覆盖这些新类名；
- **真实净空不足**：城市装饰子件、集装箱等按主楼 AABB 计算净空，子件（鳍片/雨檐/空调机组）
  悬挑超出 AABB，实际顶点压进路面走廊。

可行性：**高**。修复路径明确——统一「路肩家具白名单 + 装饰子件按顶点实测半径放大净空」，
沿用 v0.54 的审计工具自校验，不改玩法代码。

### 2. 【P0】无版本控制

- 项目无 `.git`，docs 亦无法回答「哪次改动引入了穿模回归」——本次诊断只能靠 mtime 猜测。
- 4.8GB 目录（assets/thirdparty 1.4G + cars 663M + venues 486M）建议 git + LFS 或
  git 排除 assets 目录 + 独立资产备份。
- 可行性：**高**（半小时内完成初始化与首次提交）。

### 3. 【P1】模型精度与性能的矛盾（车模 0 LOD）

- 45 台车 v0.51 高清重导后合计 **9,920,590 三角面、777 draw calls**（已按材质合并 -30%）；
  但**没有任何车模 LOD**（`car_visual.gd` 无 LOD 逻辑），赛道上 4 车 × 满面数 + 车库满模同屏；
- AI 车与玩家车共用同一满精度网格，10m 外与 200m 外渲染成本完全相同；
- README「已知限制」已自我诊断此项。这是**性价比最高的性能优化**：
  Blender 批处理减面（hero / mid / far 三档）+ `visual_server` 层级切换。
- 可行性：**高**（tools/ 已有 fetch/减面流水线先例，预期比赛帧率 +20~35%）。

### 4. 【P1】关于「替换为网上开源高精度模型」的可行性结论

现状：环境侧**已经**是开源资产（Poly Haven CC0：HDRI 天空、PBR 材质、树/礁石/建筑，
`tools/fetch_cc0_assets.py` 抓取 + Blender 减面 LOD 流水线成熟）；
车辆侧 45 台是**自有 .blend 原件高清重导**，精度与外观统一性已达标。

若坚持「全量换开源车模」，可行渠道与风险如下：

| 来源 | 协议 | 车辆质量 | 风险 |
| --- | --- | --- | --- |
| Poly Haven | CC0 | 无车模（仅环境/材质） | 无（已在用） |
| Quaternius / Kenney | CC0 | 低多边形风格化 | 与现有写实风格冲突，属**降级** |
| Sketchfab 筛选 CC0/CC-BY | CC0/CC-BY 4.0 | 少量写实车模，质量参差 | CC-BY 需逐台署名；「真实品牌车」为同人复刻，商标/外观专利风险由发布者承担 |
| glTF 官方样例 | CC0/CC-BY 4.0 | 无量产车 | 无 |

**结论与建议**：车模**不做全量替换**（外观一致性倒退 + 许可负担 + 45 台 × 重建改装件挂点
的工作量 ≈ 重做 M2），改为：
1. （P1）对现有 45 台做 **LOD 化 + 轮胎/车漆材质精修** —— 视觉收益接近换模，成本 1/10；
2. （P2）新增 1–2 台「展示级」CC0 车模作为彩蛋车，验证 Sketchfab CC0 渠道后再决定是否扩展；
3. 环境侧继续从 Poly Haven CC0 补高模资产（护栏/龙门架/维修区精细件），零许可风险。

### 5. 【P1】逻辑/玩法现状

核心循环（主菜单 → 选车/选道 → GP/计时 → 结算/纪录 → 车库成长）完整且经无头验收；
`car.gd`（659 行）街机物理带 0-100 真车标定、扭矩曲线、手动挡/断油/氮气，质量良好；
`ai_car.gd` 为**运动学样条跟随**（非物理体）——这是有意的移植决策，但意味着：

- AI 与玩家碰撞是「事后修正」而非物理响应（v0.55 已修粘连/闪现，但本质仍是补丁式）；
- AI 无失误模型：确定性配速 + 橡皮筋，跑 3 圈的可预测性偏高；
- 提升可玩性的现实路径：**给 AI 加「失误/进攻事件」层**（锁死/刹车过早/被挤线摇摆，
  参数沿用现有 skill 派生），而不是重写物理。

**状态管理**：`main.gd` 已达 2944 行，承担 应用状态机 + 菜单世界 + 比赛流程 + 烘焙 +
ACE68 桥 + 双人 + 审计 六类职责，是当前最大的可维护性债务。可行性：**中高**
（拆分为 MenuWorld / RaceSession / BootFlow 三个控制器 + 信号总线，验收有 `--verify` 兜底）。

### 6. 【P2】UI 现状

`ui_style.gd`（1078 行）已是集中式设计系统：Token 色板 / 字阶 / 间距 / 玻璃面板 /
按钮 5 态 / 程序化贴图，各界面统一取样式 —— **「组件化方案」的基座已经存在**。
缺口是：控件仍以代码拼装为主（15 个 create_* 工厂方法），没有沉淀为可复用的 `.tscn`
组件场景；主题换肤、Steam Deck 缩放适配等场景缺乏验证。可行性：**中**（渐进式抽取，
不动布局与键位，风险低）。

### 7. 【P2】画面表现现状与剩余空间

已具备：HDRI 天空 + FBM 云、SSR/SSAO/SSIL/体积雾/TAA/径向动态模糊、雨雪尘天气、
车灯/暗角/调色、暗调电影感影调、CC0 真实材质。剩余可行增强（按性价比排序）：

1. **SDFGI 全局光照**（Godot Forward+ 原生支持）：静态场景一次辐射缓存，
   城市楼间/峡谷岩壁的间接光质感会明显提升；比赛帧率代价需实测（预估 -8~15%），
   建议仅 ULTRA 档开启；
2. **Decal 轮胎印与磨痕**：漂移/重刹处贴 Decal（项目 README 已列为待办），
   每帧限量池化即可控成本；
3. 车漆细节：金属清漆 + 薄膜干涉（Godot 4 次表面散射/车漆着色器已有社区方案）；
4. 阴影质量：directional shadow 8192 已到位，可加 contact shadow 距离微调。

可行性：1、2 为**中**（需帧率实测与池化），3、4 为**高**（纯材质/参数）。

### 8. 【P3】包体与发布

- 导出模板未下载（README 已注明），出包管线脚本就绪；
- 4.8GB 源资产 → Android APK 必然超标，需要纹理压缩（ASTC）+ thirdparty 减容审计；
- `physics_ticks_per_second=120`：车辆是运动学自写物理，实测确认 60Hz 是否影响手感
  （若可降，物理线程开销近似减半）。

## 三、优化方案（按优先级）

| 优先级 | 项 | 内容 | 可行性 | 预期收益 | 验收 |
| --- | --- | --- | --- | --- | --- |
| **P0-1** | 穿模审计回归修复 | 路肩家具白名单（gravel/reflector/tire-wall 类按设计意图豁免或外移）+ 城市装饰子件/集装箱按顶点实测半径放大净空 | 高 | `--verify` 8 图回到 0 违规 | `[VERIFY] PASS` |
| **P0-2** | 版本控制 | git init + 首提 + assets LFS/排除策略 + 每次迭代一提交的纪律 | 高 | 消灭「不可逆丢失」风险 | repo 建立 |
| **P1-3** | 车模 LOD | 45 台 × 3 档减面（hero 100% / mid ~40% / far ~15%），距离切换 + 车库恒用 hero | 高 | 比赛 fps +20~35%，ULTRA 稳 60 | 帧率对比 + 外观截图 |
| **P1-4** | 模型资源策略 | 车模不全量替换，做 LOD+材质精修；环境继续补 Poly Haven CC0；试引 1–2 台 CC0 彩蛋车验证渠道 | 高/中 | 视觉升级且零许可风险 | 来源与协议记录进 docs |
| **P1-5** | main.gd 拆分 | MenuWorld / RaceSession / BootFlow 三控制器 + 信号总线，行为不变 | 中高 | 可维护性、后续功能提速 | `--verify` 全绿 + 手感回归 |
| **P1-6** | AI 失误层 | 基于 skill 派生失误概率（刹车过早/锁死/被挤摇摆），替代部分橡皮筋 | 中 | 单圈可变性强、超车机会真实 | 10 圈统计超车次数 ↑ |
| **P2-7** | UI 组件化 | create_* 工厂沉淀为 .tscn 组件（Button/Panel/Toggle/HUD 仪表卡），支持缩放档 | 中 | 换肤/适配成本下降 | 截图对比 + DPI 缩放测试 |
| **P2-8** | 画面增强 | SDFGI(仅 ULTRA) + Decal 轮胎印 + 车漆着色器 + contact shadow | 中 | 光影质感接近「商业品相」 | 逐项 fps 实测表 |
| **P2-9** | 玩法打磨 | 漂移评分、近距超车奖励、圈速幽灵车（records.json 已存最佳圈） | 中 | 计时赛深度 | 无头 + 手动验收 |
| **P3-10** | 发布管线 | 导出模板下载、ASTC 纹理、thirdparty 减容、Android 出包 | 中 | 可分发安装包 | 三平台包产出 |
| **P3-11** | 赛道高程 | 控制点加 Y 分量 + 路面/护栏/相机/物理全链适配 | 低 | 坡道过弯的玩法维度质变 | 单赛道试点（先 1 条） |

> P3-11 是唯一能带来「玩法代际差异」的项，但工作量 ≈ M1 重来一遍，建议作为
> v1.0 后的独立里程碑评估，本轮不做。

## 四、建议实施顺序

```
第一批（稳定底座）   P0-1 → P0-2 → 全量回归（--verify / --audio-test / 手感抽查）
第二批（性能与外观） P1-3 → P1-4（环境补件）→ P2-8（逐项实测帧率）
第三批（玩法与结构） P1-6 → P2-9 → P1-5（重构放最后，避免中途冲突）
第四批（发布）       P3-10
```

每批完成后跑一次 `--verify` + 1600×900 四档帧率记录，写入 docs 形成基线曲线。

## 五、结论

- 当前最危险的不是画面，而是**审计红灯与无版本控制**——先修 P0；
- 「开源高精度模型全量替换」**不建议执行**：环境侧已 CC0 化，车模侧替换的收益/成本比
  远低于 LOD 化 + 材质精修，且引入署名与品牌外观合规负担；
- 以现有技术栈，可达目标为「稳定 60fps 的商业街机赛车品相」，缺口主要在
  LOD、SDFGI/Decal 级渲染增强与 AI 可变性，均在本方案 P1/P2 内闭环。

—— 待确认后按上述顺序逐步实施。
