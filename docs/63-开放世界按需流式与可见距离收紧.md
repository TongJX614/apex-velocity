# 63 · 开放世界：布景按需流式生成与可见距离收紧

> 关联文档：`59-无界大陆_开放世界.md`、`60-开放世界过渡与实体碰撞.md`
>
> 用户反馈「很卡」+ 两点诉求：进某条赛道时别的赛道不要在后台加载；
> 大地图走到哪生成到哪，远处不生成。本轮按这两点实施并实测。

---

## 〇、结论速览（实测数据）

| 指标 | 修复前（全量常驻） | 修复后（流式 + 分类收距） |
|---|---|---|
| 帧内绘制面数 | 3499 万/帧（低画质档实测） | **333 万/帧**（ULTRA 实测） |
| draw calls | 1787 | **524** |
| 平均 fps | 5.4（低画质半分辨率） | **14.7（ULTRA 全分辨率）/ 25.0（high）** |
| 开局布景构建 | 全部 8 域 + 8 过渡带 4.8s / 1.77 万实例 | 出生域周边 7 单元 **3.7s / 6261 实例** |
| 后台加载 | 菜单预载相邻两条赛道 | **移除**，只异步载当前切换目标 |

碰撞体不受流式影响：静态碰撞注册在独立的哈希表里，远处单元被隐藏后
楼照样撞得上；新单元建成即注册，车永远撞不到「还没生成的楼」。

## 一、菜单赛道后台预载：移除

`main.gd` 原本在菜单空闲时后台构建相邻赛道的场景（`_preload_menu_neighbours`
+ `_preload_queue`），意图是切图秒开。实际效果是菜单背后同时挂着
三份赛道世界（沙盘 + 当前 + 预载），菜单本身也掉帧，且切图并不
真正变快（构建本来就走异步分步）。

改动：删除预载队列与邻居预载函数；保留「切到哪条就异步载哪条」
（`_start_menu_preload`）和菜单沙盘缓存裁剪（`_trim_menu_cache`，≤4 份）。

## 二、开放世界布景流式：走到哪，建到哪

### 2.1 单元划分

布景按 **16 个流式单元** 组织：8 个域单元（`zone_0..7`，半径取域半径）
+ 8 个过渡带单元（`band_0..7`，中心取相邻两域中点）。原来
`OpenWorldScenery.build()` 一次建完全部 16 个单元（1.77 万实例、
7781 个 MultiMesh 节点、合计 1.26 亿三角面），现在拆成：

- `build_initial(world, parent)`：开局只建「出生点 + INITIAL_RANGE
  (3200m) 内」的单元（出生域 + 相邻过渡带，3.7s），替代原来 4.8s 全量；
- `stream_tick(world, pos, dt)`：每帧由 `_update_open_world` 驱动，
  距玩家 ≤ 半径 + `STREAM_TRIGGER` (1700m) 的未建单元开始构建，
  单次最多建 1 个、间隔 0.25s，避免一次构建卡帧；
- 距离迟滞：远离至半径 + `HIDE_EXTRA` (2400m) 整单元隐藏，
  回到半径 + `SHOW_EXTRA` (2100m) 再显示——建过的不重建，
  隐藏/显示只是容器 `visible` 开关，成本为零。

### 2.2 碰撞与流式解耦

静态碰撞注册（`_register_colliders` → `open_world._collider_hash`）
与可见性无关：隐藏单元的楼照样参与碰撞查询，新增单元建成即注册。
`_run_open_world_test` 的两处传送点后补了 `ensure_units_at(..., 3200.0)`，
保证截图/碰撞测试点的布景已就位。

### 2.3 画质档与剔除器联动

- `_start_open_world` 里把扇区剔除器收紧：`max_distance = 1600`、
  `tight_sector = true`（城市图分块大，默认侧向余量 0.55rad 下
  扇形张角接近 230°，剔无可剔）；
- `_apply_quality` 换画质档时对开放世界保持上述收紧值
  （普通赛道仍用 `Settings.far_distance()`），不再被通用远景覆盖。

## 三、可见距离按「树 / 楼 / 地标」分类收紧

### 3.1 为什么要分类

资产面数实测（`tools/ow_asset_tri_report.gd` 全量统计）：
树占全部面数 **51.5%**（realtree_01/02/03 + broadleaf，单棵 1.3万~10万面）、
楼占 **25%**（downtown 系列 + station_tower，单栋 1.6万~5.6万面）。
旧逻辑只有一个统一 `VIS_SCALE = 0.5`，树和楼一视同仁，
而树恰恰是最该收的东西。

### 3.2 分类系数（最终可见距离 = vis_end × 系数，各画质档一致）

| 类别 | 系数 | 最终距离示例 |
|---|---|---|
| 楼（NeonBlock / SkyBlock / SkyApt / HarborShed / AlpineHut / MagmaRefinery / MagmaPipe） | 0.22 | 2200×0.22 = **484m** |
| 树（StreetTree / TransitionTree / 各域乔木 / 灌木） | 0.34 | 900×0.34 = **306m** |
| 地标（NeonHero / HarborBridge / HarborTower / HarborShip / FrozenShip） | 0.45 | 3000×0.45 = **1350m** |
| 其余（岩石 / 码头 / 标记 / 桶 / 轮胎墙等小件） | 0.30 | 1800×0.30 = **540m** |

远景有雾压着，楼收得最狠，树次之；地标塔保留地平线剪影。
`RealAssetKit.quality_mul()`（LOW 0.75 → ULTRA 1.5）这次**不再放大**
开放世界的绘制距离——9×9km 的图上画质档一放大就是几百万面——
`_place` 传参按当前档位归一化，各档实际可见距离一致，
画质差异交给分辨率与后效。

### 3.3 与原方案的对照

| 方案 | LOW 实测 | ULTRA 实测 |
|---|---|---|
| 旧：统一 0.5 × 画质系数放大 | 657 万面 / 20.2fps | 2964 万面 / 3.1fps |
| 新：分类系数、各档一致 | — | **333 万面 / 14.7fps** |

（旧方案 ULTRA 数字为推算交叉验证：perf2 在 LOW 档测得 657 万面，
同场景切 ULTRA 后可见范围翻倍、实测 2964 万面，即 perf3。）

## 四、剩余瓶颈与后续方向

ULTRA 档剩余开销在**后效栈**而非几何：同场景 high 档（SSR 64 步、
阴影 240m、无树影）25.0fps，ULTRA（SSR 128 步、阴影 460m、树影、
体积雾、SSIL）14.7fps，面数几乎相同（314 万 vs 333 万）。
后续对应 docs/57 的 P1-3（车模 LOD，AI 车与玩家车同为满精度网格）
与 P2-8（后效分档实测），本轮不动。

Pop-in 由单元级迟滞 + 分块级 `visibility_range_end_margin` 双层缓冲，
流式构建间隔 0.25s 单元级错峰；实测 `--openworld-test` 各域截图
布景完整、碰撞测试通过（见 [OW-TEST] 输出）。

## 五、回归验证

- `--openworld-test`：8 域 + 3 过渡带截图完整，碰撞 10100 个，
  楼内推出 gap 1.45m ≥ 1.45、40m/s 撞墙位移 10.97m → 10.97m（挡住）。
- `--verify`：赛道穿模审计全绿（含 open_world）；仅有的 2 项 FAIL
  （metro 赛道 only 2 meshes、garage save/load roundtrip）与本轮改动无关，
  系另一并行会话的进行中工作。
- 普通赛道布景经由同一 `RealAssetKit.place_chunked`（本轮仅把画质系数
  抽成 `quality_mul()`，公式不变），行为无变化。
