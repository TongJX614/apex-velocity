# 62 · 零件人工调参器（part_tuner）

> 2026-11-07 ~ 11-08 · 用户：「尾翼装上去位置不对、有的车根本装不了，我要自己看着调。」
> 本文记录 `tools/part_tuner/` 这套**人眼当裁判**的调参工具：界面、键位、数据契约、
> 生效链路、禁用标记语义、自检脚本与当前数据覆盖度。

---

## 一、为什么需要人工调参

45 台车 × 8 颗供体翼 = 360 种装配组合。程序化生成只能保证**几何合法**（不穿模、不悬空），
保证不了**视觉合理**：不同车的行李箱面高度、尾门倾角、车宽差异极大，
同一颗翼在 A 车上位置正好，在 B 车上就压进后备箱或翘在半空。

规则算法调不出「看着对」，只有人眼能判断。所以这套工具的设计目标是：

| 设计目标 | 实现方式 |
| --- | --- |
| 改完立刻看见 | 每次按键直接重建挂装，不重启、不导表 |
| 只改差异，不改规则 | 规则仍由 `PartsLibrary` 算基准位，人工数据只叠加 Δ |
| 数据可回滚 | 全部数值落在 `data/part_offsets.json`，纯 JSON，可 diff |
| 不误伤存档 | 自检脚本测试前后自动还原 `garage.json` 与标记现场 |

## 二、启动方式

**双击项目根目录 `启动尾翼调参.command`**，或命令行：

```bash
GODOT=~/Applications/Godot.app/Contents/MacOS/Godot
"$GODOT" --path /Users/tong/Desktop/极速巅峰 res://tools/part_tuner/part_tuner.tscn

# 直达某台车
"$GODOT" --path . res://tools/part_tuner/part_tuner.tscn -- --car=bmw_m4_gt4
```

场景极简（`part_tuner.tscn` 只有一个挂脚本的 `Node`），环境、相机、UI 全部由
`part_tuner.gd`（约 43KB）在 `_ready()` 里用代码构建：中性灰背景 + 单方向光，
与 `wing_check` 同一套打光，避免"调的时候一个色、游戏里另一个色"。

## 三、界面与操作

### 3.1 鼠标

| 操作 | 作用 |
| --- | --- |
| 左键点选 | 点任意一条轮胎 = 选中**四条**（按前后轴分组）；点尾翼 = 选中**翼组** |
| 右键拖动 | 轨道旋转视角 |
| 滚轮 | 缩放（视线距离）；**删除模式下**改为调节格边长 |
| Shift/Alt/Ctrl 点选 | 选区增删：强制把该节点加入/排除出部件组（写入 `*_pick`） |

### 3.2 键盘

| 按键 | 作用 |
| --- | --- |
| `↑` / `↓` | 选中件**升高 / 降低**（默认 1cm，Shift 5cm） |
| `←` / `→` | 选中件**后移 / 前移**（默认 1cm，Shift 5cm） |
| `Q` / `E` | 尾翼：**缩小 / 放大**（默认 3%，Shift 10%）<br>车轮：**内收 / 外扩**（左右轮自动镜像） |
| `[` / `]` | 切换上一颗 / 下一颗尾翼供体 |
| `,` / `.` | 切换上一套 / 下一套车轮供体 |
| `C` | 下一台车（车辆清单侧栏也可直接点） |
| `Enter` / `S` | 保存到 `data/part_offsets.json` |
| `R` | 重置当前选中（尾翼=偏移+缩放归零；车轮=清该轴偏移） |
| `Esc` | 取消选中；删除模式下先取消格子选择 |
| `+` / `-` | 拉近 / 拉远 |

> 原厂部件不可调：选中 `stock` / `factory` 时按方向键会提示「先切到一个改装件」，
> 这是刻意设计 —— 原厂件位置来自模型本身，改它等于改车模。

### 3.3 状态提示

顶栏显示当前车 / 翼 / 轮供体与实时偏移值；左下角有「未保存（Enter 保存）」黄字，
保存成功后变为「✓ 已保存，游戏内立即生效」并在 2 秒后淡出。

## 四、数据契约：`data/part_offsets.json`

一棵以 **车 id** 为根的树，45 台车各占一个键。字段全部可选：

```jsonc
{
  "bmw_218i": {
    "done": true,                        // 人工标记「这台车调完了」
    "wing": {                            // 尾翼偏移，按【供体车 id】分桶
      "bmw_m4_gt4": { "dy": -0.10, "dz": -0.08, "scale": 0.85 }
    },
    "wheels": {                          // 车轮偏移，供体 id → 前/后轴
      "bmw_i8_lb": { "front": { "dx": -0.05, "dy": 0.0, "dz": 0.0 } }
    },
    "cuts": [                            // 空间删除：按三角形索引切除
      { "node": "CarRoot/b_Kit4_..._lodA", "surf": 0, "tris": [1949, 1950] }
    ],
    "no_wing": true,                     // 车级：这台车游戏内选不了尾翼
    "wing_bans": ["bmw_m5_f90"],         // 配对：这台车装不了这颗翼（其它车不受影响）
    "wing_pick":   { "add": [], "del": [] },   // 选区人工增删（规则漏选/多选）
    "wheels_pick": { "add": [], "del": [] }
  }
}
```

**坐标语义**：`dy` 为垂直、`dz` 为纵向（车头方向）、`dx` 为横向；
全部是**相对程序化基准位的偏移量（米）**，不是绝对坐标。基准位由
`PartsLibrary.build_wing / build_wheel` 按车宽车长实测算出，所以换车不需要重调。

`scale` 缺省为 1.0；尾翼缩放是为了让同一颗翼适配不同车宽（从 ×0.50 到 ×1.12 都在用）。

## 五、生效链路

```
part_tuner（人眼调参）
   └─ Enter ─► PartsLibrary.save_offsets()
                 └─► res://data/part_offsets.json
                        ├─► PartsLibrary.build_wing()   基准位 + Δ
                        ├─► GarageLook.apply()          换件时叠加
                        └─► CarVisual                   隐藏旧翼 / 执行 cuts
```

关键点：**游戏内不重新导入、不需要重启编辑器**。`PartsLibrary` 首次访问时读取
JSON 进静态缓存（`_ensure_offsets()`），保存写盘后下一次挂装即生效。
工具里 `_apply_and_refresh()` 走的也是游戏同一条 `GarageLook.apply()` 路径，
所见即游戏所得。

## 六、空间删除模式（✂）

有些车模的原厂尾翼是**焊在车身网格里**的，靠隐藏节点去不掉，只能把那一块三角形切掉。

| 步骤 | 操作 |
| --- | --- |
| 进入 | 点顶栏「空间删除」按钮 |
| 调格 | 滚轮改格边长，范围 **4mm ~ 50cm**（默认 15cm） |
| 选格 | 左键点选一个格子（红色高亮），或方向键移动当前格 |
| 确认 | `Enter` 或再次点击该格 → 删除格内三角形 |
| 撤销 | 「撤销删除」按钮（只回退最近一次） |

实现细节：

- 用世界坐标 AABB 判定三角形**任一顶点**落在格内即删除 —— 不做精确三角形裁剪，
  保证边缘干净不出现半张面；
- 单轴最多绘制 100 格格线，过细时只画准星附近，避免百万线段把编辑器卡死；
- 删除记录按 `{node 路径, surface 索引, 三角形索引数组}` 存盘，与网格拓扑绑定 ——
  **换车模必须重做 cuts**，否则会切错面。

## 七、禁用标记语义

两类标记，容易混淆，这里分清：

| 标记 | JSON 字段 | 游戏内表现 | 当前数量 |
| --- | --- | --- | --- |
| 车级禁翼 | `no_wing: true` | 这台车尾翼入口锁死在原厂，`cycle` 左右都动不了 | 15 台 |
| 配对禁装 | `wing_bans: ["供体id"]` | 这台车切翼时跳过该供体，其它车仍可正常选用 | 23 条 |

判断标准：**这颗翼在这台车上怎么调都不好看** → 用配对禁装；
**这台车根本不该有改装尾翼**（MPV、方盒子 SUV、原厂大尾翼超跑）→ 用车级禁翼。

两个按钮点击即写盘（不等 Enter），避免误关窗口丢标记。

## 八、自检脚本

四个 `extends SceneTree` 的无头脚本，位于 `tools/part_tuner/`：

| 脚本 | 验证内容 |
| --- | --- |
| `wingban_selftest.gd` | 甲车禁装翼 X 后，甲车 cycle 跳过 X、乙车不受影响；车级禁翼时左右都锁在原厂。测完自动还原 `garage.json` 与标记现场 |
| `cut_mode_selftest.gd` | 进入删除模式 → 滚轮调格 → 点格 → 方向键移动 → 回车删除 → 撤销，全流程不落盘 |
| `final_apply_check.gd` | 终检：`varis_m4_gts` 的 6 条切除真实生效、`bmw_m4_gt4` 换翼位置 = 基准 + Δ、抽查禁装配对。只读 |
| `cut_probe.gd` | 三角形计数探针，对比切除前后面数 |

运行：

```bash
GODOT=~/Applications/Godot.app/Contents/MacOS/Godot
"$GODOT" --headless --path . --script res://tools/part_tuner/wingban_selftest.gd
"$GODOT" --headless --path . --script res://tools/part_tuner/final_apply_check.gd
```

> 坑：`--script` 主循环脚本的**编译早于 autoload 注册**，脚本里不能直接写 `GameData` /
> `Garage` 全局标识符，必须在运行时用 `root.get_node("/root/GameData")` 取节点。
> 这也是四个自检脚本开头都有一行「运行时取 autoload」注释的原因。

## 九、备份与恢复

工具保存是**直接覆盖** `data/part_offsets.json`，不自建历史版本。当前手工快照在：

```
data/backups/part_offsets_2026-11-08_0049.json   精确数据（机器可读）
data/backups/调参数据备份_2026-11-08.md          人读快照（逐车表格）
```

恢复方式：把备份 JSON 复制回 `data/part_offsets.json` 即可完全还原。

**建议**：下次大改前先 `cp data/part_offsets.json data/backups/part_offsets_$(date +%F_%H%M).json`。
这套工具没有做自动轮转备份，属于已知缺口（见第十一节）。

## 十一、已知缺口

1. **无自动备份轮转** —— 覆盖保存，靠手工快照兜底；
2. **cuts 与网格拓扑强耦合** —— 车模重新导出后三角形索引会变，必须重做切除；
3. **`bmw_m4_gts` 残留空 `cuts: []`** —— 无副作用，但建议清理保持数据干净；
4. **无批量操作** —— 45 台车逐台调，单台 8 颗翼，全量重调约需 2~3 小时；
5. **只在 macOS 上验证过** —— 工具本身是纯 Godot，跨平台理论可行，但未实测。
