# 49 · 场景装饰编辑器（v0.50）

> 2026-11-05 · 用户：想在 Godot 里自己改地图（场景装饰：树、房子、广告牌）。

## 一、先说清楚两件事

### 1. Godot 不是建模软件

Godot 的 3D 视口是**场景组装器**：能摆放已有模型、缩放旋转、用 CSG 做基本体布尔。
它没有挤出面、切边环、雕刻、拓扑编辑这些能力。项目里的树、石头、楼体都是
Blender 减面后导出的 `.glb`，Godot 只负责摆。要新建模型仍然得回 Blender。

### 2. 打开这个项目，3D 视口是空的

`scenes/main.tscn` 完整内容只有 174 字节：

```
[node name="Main" type="Node3D"]
script = ExtResource("1_main")
```

一个空节点挂 `main.gd`。整张地图是**运行时用代码生成**的：

```gdscript
var builder := TrackBuilder.new()
race_root.add_child(builder)
track_path = builder.build(track_def)          # 沿中心线扫出路面
SceneryKit.build(race_root, track_path, ...)   # 撒树、草、石头
VenueKit.build(race_root, track_path, ...)     # 摆看台、护栏、广告牌
```

赛道形状来自 `data/tracks.json` 的 `points`（20~32 个 `[x, z]` 控制点），
Catmull-Rom 样条展开成闭合环，路面 / 护栏 / 植被 / 看台全部沿这条中心线扫出来。

所以「在 Godot 编辑器里拖地图」这件事在当前架构下**做不到** —— 没有可拖的节点。
要做，得先把程序化生成的结果变成可寻址、可持久化的实体。

## 二、本次交付：场景装饰编辑器

### 设计取舍

装饰本来有两万个实例（草占 20200，树 / 灌木 / 道具约 1500）。
把全部实例烘焙成数据文件既臃肿又脆弱，所以采用**增量 override**：

- 装饰继续程序化生成（固定随机种子，同一条赛道每次顺序一致）；
- 只记录用户**动过**的那几条：`(组名, 分块, 实例序号) → 新变换`；
- 游戏加载完场景后，按同样的键找回去覆盖。

代价：改了 `tracks.json` 的赛道形状后，实例数量与分组会变，旧 override 可能对不上号。
表现为某条改动失效或错位到别的物体上，这时重新编辑即可。

### 关键标识

一个资产（比如棕榈）会被拆成多个 surface 节点 `s0 / s1 / s2`，
它们装的是**同一批实例**。如果按节点名做 key，拖动时只有其中一个面会跟着走，
看起来像「树炸开了一半」。所以 key 用 `组名 + 分块 + 实例序号`：

```
MM:CoastPalms__tree_palm_tall_g3#7   ← 资产组、第 3 分块、第 7 个实例
MM:ad_board_5#12                     ← VenueKit 一次摆放批次里的第 12 个
MM:Prop_GuardrailPosts#40            ← 手搓 MultiMesh 道具
ND:CoastLookoutDeck                  ← 独立节点（看台、楼体、广告牌）
```

> **v0.49 修正**：组名里必须带资产名或批次号。
> 海边棕榈曾经让 `tree_palm_tall` 和 `tree_palm_bent` 共用 `"CoastPalms"` 这个前缀
> 摆同一批点，两组实例的 key 完全撞车 —— 结果编辑器里只能选中高个那种棕榈，
> 弯的那种点上去毫无反应。现在 `place_chunked` 会把资产名编进组名，
> 任何前缀复用都不会再串。

识别哪些对象可编辑，不靠节点名猜（`Ground` / `LaneMarking` / `@MeshInstance3D@82`
这些会一直误收基面构件），而是靠生成时打的 `decor_asset` 元数据标记。
**三条摆放路径都必须打标记**，漏一条就表现为「画面上明明有这棵树，却点不中」：

| 路径 | 负责什么 | 状态 |
| --- | --- | --- |
| `RealAssetKit.place_chunked` | 植被、礁石、浮标、栈桥（glb 资产） | v0.47 已标 |
| `VenueKit._place_repeated` | 赛道边的树、广告牌、灯柱、旗杆、轮胎墙 | **v0.49 补标** |
| `SceneryKit._prop_mm*` | 海滩伞、毛巾、救生塔、集装箱、龙门架等手搓道具 | **v0.49 补标** |

补标之后海岸赛道的可编辑实例从 46 涨到 310，其余赛道 250~600。

### 新增文件

| 文件 | 作用 |
| --- | --- |
| `scenes/decor_editor.tscn` | 编辑器场景（单个 Node3D + 脚本） |
| `scripts/tools/decor_editor.gd` | 编辑器：模型库、拾取、拖动、旋转、缩放、删除、**撤销/重做**、保存 |
| `scripts/tools/decor_overrides.gd` | override 的读写与应用层，游戏和编辑器共用；含 `added` 重建 |
| `data/decor/overrides/<track>.json` | 用户改动，运行后自动生成 |
| `双击编辑地图.command` | 双击启动并选择赛道 |

override 文件结构：

```json
{
  "track": "coast",
  "edits":   [ { "key": "MM:CoastPalms__tree_palm_tall_g3#7", "p": [...], "q": [...], "s": [...] } ],
  "removed": [ "MM:CoastBuoys_g5#0" ],
  "added":   [ { "id": "a1", "asset": "realtree_01", "p": [...], "q": [...], "s": [...] } ]
}
```

`added` 在 `apply()` 里**最先处理**：先把模型摆出来，再建索引，最后套 `edits`。
这样自己摆放的模型也能被同一条 `edits` 记录移动和缩放，不必单独维护一套逻辑。

### 改动文件

- `scripts/tracks/real_asset_kit.gd`：`place_chunked` / `place_unique` 打
  `decor_asset` / `decor_group` / `decor_chunk` / `decor_surface` 元数据
  （组名带资产名，避免前缀复用撞车）；新增 `capture_*` 采集接口与 `category_of()` 分类；
  新增 `_pack_via_gltf()` 运行时解析未导入的 glb、`instance()` 统一实例化入口。
- `scripts/tracks/venue_kit.gd`：`_place_repeated` 补打可编辑标记，

- `scripts/tracks/scenery_kit.gd`：`_prop_mm` / `_prop_mm_custom` 补打可编辑标记
  （`_tag_prop`），覆盖海滩伞、毛巾、救生塔、集装箱、龙门架等手搓道具。
- `scripts/core/main.gd`：菜单预览与比赛世界构建完成后调用 `DecorOverrides.apply()`；
  新增 `--bake-decor` 烘焙模式。
- `scripts/tracks/track_builder.gd`：**未改动**（护栏柱属于赛道本体，故意不纳入编辑）。

## 三、使用

双击 `双击编辑地图.command` → 选择赛道 → 打开编辑器。

打开后视角落在起跑线旁的路面上方。**这一点很关键**：早先版本是「俯视整条赛道」，
海岸赛道跨度 710m，相机被抬到 440m 高空，一棵 8m 高的树在 1600×900 画面上只有
十来个像素，鼠标根本压不中，看起来就像「编辑器没法用」。

| 操作 | 说明 |
| --- | --- |
| 鼠标悬停 | 实时黄框预览「这个东西可以点」 |
| 左键 | 点选装饰；按住拖动则沿地面移动 |
| F | 把镜头推到选中项（或鼠标下的对象）旁边 |
| N / Shift+N | 跳到下一个 / 上一个可编辑对象 |
| Tab | 显示 / 隐藏可编辑对象头顶的黄色标记 |
| R / Shift+R | 绕 Y 轴旋转，一步 15°（**按住可连续转**，110ms 节流） |
| **G** | **摆正**：清掉倾斜、只保留绕 Y 的朝向 |
| `[` / `]` | 缩小 / 放大 10%（按住可连按） |
| Delete | 删除选中项 |
| **Ctrl+Z / Cmd+Z** | **撤销**一步（连续旋转、拖动一次都只算一步） |
| **Ctrl+Shift+Z / Cmd+Shift+Z** | **重做**（`Ctrl+Y` 也行） |
| Ctrl+S | 保存到 `data/decor/overrides/<track>.json` |
| WASD / QE | 移动相机 / 升降 |
| 右键拖动 | 旋转视角 |
| 滚轮 | 推拉相机 |
| Esc | 取消放置模式；再按一次退出（**有未保存修改时需按两次**） |

HUD 会实时显示选中项的 **朝向 xx° · 缩放 x.xx×**，按 R 转了没有一眼就能看出来。
第二行还会显示 **可撤销 N 步 · 可重做 N 步**，有改动未保存时后面挂 **● 未保存**。

### 撤销 / 重做

实测下来最常见的翻车是「手滑把树拖到海里」或「多按了两下 R」，所以做了完整的撤销栈。

实现上**不是**用「反向命令」，而是**整盘状态快照**：每次动之前把
`edits` / `removed` / `added` / `next_add_id` 连同**每个实例的世界变换**一起存一份
（约 50KB，上限 80 步，四舍五入几 MB 内存）。原因是三条改动的「逆操作」形态完全不同 ——
删除是「记 `removed` + 缩到 0.0001」，摆放是「新建整棵节点树」，快照法一视同仁，不会漏。

还原时按固定顺序来，顺序错了会错位：

```
对齐 Added_* 节点（多余的销毁 / 缺的重建）
  → 重新收集索引（节点变了，items 下标会整体位移）
  → 重建头顶标记
  → 逐个把快照里的世界变换写回实例
```

几个细节：

- **连续手势合并成一步**。按住 R 连转、拖一下鼠标，都只占一格撤销 ——
  否则一次连转能塞进几十步，撤起来要按到手软。判据是「同 tag 且间隔 < 900ms」。
- **只点一下不拖动不占撤销格**。拖动要等鼠标真的位移了才入栈，
  不然点着玩几次就能把撤销栈填满，按下去像没反应。
- 删掉东西后撤销，连**选中状态**一起恢复，不用再找一遍。
- 撤销 / 重做只在内存里生效，**要落盘仍然按 Ctrl+S**。

### 从项目库摆放模型

编辑器右侧是**项目库模型**面板，列出 `res://assets/venues/` 下全部 `.glb`
（当前 74 个），带搜索框过滤。

面板顶部是**预览区**：鼠标在列表里划过哪个，就显示哪个模型的离屏渲染缩略图 +
实际尺寸（如 `4.8 × 5.0 × 4.8 m`）。在场景里点中一棵树时，预览也会自动切过去。

- 缩略图是运行时用独立 `SubViewport` 逐帧拍的，缓存到
  `user://decor_thumbs/v1/`（PNG + sizes.json），第二次启动直接读图。
- 缓存目录带 `v1` 版本号，以后改了灯光/构图改成 `v2` 即可，旧缓存自然失效。
- 列表每行也带 36px 小图标，滚动时不必逐条读名字。

1. 在列表里点一个模型 → 进入放置模式（HUD 顶部会显示模型名）；
2. 在地面点击即可摆放，**可以连续点、连续放**；
3. 摆好的模型和原有装饰一视同仁：能选中、拖动、旋转、缩放、删除；
4. `Esc` 退出放置模式，`Ctrl+S` 保存。

摆放的模型走 `RealAssetKit.place_unique()`，保留完整节点树与原始材质
（不是 MultiMesh，所以每个都是独立的、可单独调整的实体）。

### 导入自己的模型

面板上的 **「＋ 导入模型（.glb）」** 按钮 → 选本机文件 → 自动拷进
`assets/venues/` → 立刻出现在列表里，可以直接摆放。

- 只接受 **`.glb`（自包含单文件）**。`.gltf` 会引用外部 `.bin` 和贴图，
  单文件拷过去必然缺资源，请在 Blender 里导出成 glb。
- 同名文件不会覆盖，自动加 `_2`、`_3` 后缀。
- 技术要点：Godot 的导入流水线只在**编辑器进程**里跑，运行时新拷进来的 glb
  用 `load()` 是拿不到的。所以 `RealAssetKit._packed_scene()` 加了兜底 ——
  用 `GLTFDocument` 现场解析再 `PackedScene.pack()`，下游拆分逻辑完全无感。
  下次用 Godot 编辑器打开项目时，它会自动补 `.import`，之后就走正常加载。

### 两种删除的差别

| 对象 | 删除行为 |
| --- | --- |
| 程序化生成的装饰（树、浮标…） | 登记到 `removed`，实例缩到 0.0001 隐藏。下次启动它还会被同样的种子重新生成，所以必须靠记录压制 |
| 自己摆放的模型 | 直接销毁节点、抹掉 `added` 记录，真正消失 |

## 四、验收

- `--editor --quit`：0 SCRIPT ERROR
- `--decor-selftest`：移动 → 保存 → 重新读回，坐标一致 `PASS`
- `--decor-addtest`：放置 → 保存 → 读回 → 重新索引，`PASS`
- `--decor-applytest`：清掉 `Added_*` 后调 `DecorOverrides.apply()`，`0 -> 1`，`PASS`
- `--decor-rotest`：连转 6 次 15° = 90°、连缩放 3 次 1.1 = 1.331、
  人工转歪 25° 后按 G 归零，`PASS`
- `--decor-importtest`：外部 glb 拷入 → 列表出现 → GLTFDocument 解析出尺寸
  `3.86 × 3.40 × 4.07` → `place_unique` 成功 → 清理，`PASS`
- `--decor-undotest`：移动/撤销/重做坐标一致、连转 3 次 15° 一次撤回到原朝向
  （`+45°` → `回原样`）、删除后撤销归位且 `removed` 清空、摆放后撤销节点消失、
  重做又回来、`Ctrl+Z` / `Ctrl+Shift+Z` 按键路由，全 `PASS`
- 可编辑实例数：海岸 310 / 峡谷 602 / 冰川 501 / 高山 486 / 天际 430 /
  岩浆 342 / 港口 307 / 城市 259

> **验证时必须用 `--rendering-driver metal`。** headless 的 dummy 渲染器不保留
> MultiMesh 的实例缓冲，`get_instance_transform()` 一律返回单位矩阵，
> 查出来所有装饰都在原点，会误判成坐标 bug。

## 五、限制与后续

- **只覆盖装饰，不覆盖赛道形状**。改弯道仍然要改 `data/tracks.json` 的 `points`。
  浏览器版拖点编辑器在 `tools/track_editor.html`（`python3 -m http.server 8848`
  后访问 `http://localhost:8848/tools/track_editor.html`），能拖控制点、看实时长度与
  最急弯半径、导出 `tracks.json`。
- **新增模型用完整节点树**（`place_unique`），不是 MultiMesh。放十几个没问题，
  成百上千个会明显掉帧 —— 大批量装饰仍应走程序化生成。
- **拾取是 CPU 端逐实例射线-AABB 求交**，现在每条赛道几百个实例，
  每帧一次全量遍历无压力；上千以后需要加空间划分。
- **草和护栏柱仍不可编辑**。草两万个实例，手改没有意义；
  护栏柱（558 根）是 `TrackBuilder` 沿赛道每 N 米自动生成的赛道本体，
  挪一根破坏连续感，故意排除。
- 改 `tracks.json` 的赛道形状后，`MM:` 类 key 可能对不上号；`ND:` 类
  （含自己摆放的模型）不受影响。
